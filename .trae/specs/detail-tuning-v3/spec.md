# WeaveMD 细节调优 V3 - 产品需求文档

## Overview

- **Summary**: 对 WeaveMD Markdown 编辑器进行重大交互体验升级，移除传统的编辑/预览双栏模式，采用类似 Typora 的即时编辑体验：光标在区块内时显示原始语法，离开时自动隐藏语法标记呈现美化效果。同时优化浮动工具栏位置。
- **Purpose**: 提供更流畅、更直观的 Markdown 编辑体验，消除编辑与预览的分离感，让用户专注于内容创作。
- **Target Users**: 使用 WeaveMD 进行 Markdown 笔记和文档创作的用户。

## Goals

1. 实现即时编辑体验：光标进入区块时显示原始 Markdown 语法，离开时隐藏语法标记
2. 简化界面：移除预览模式切换，统一为单一编辑视图
3. 优化工具栏位置：进一步缩小与选中文本的间距，并向右调整位置
4. 保持现有功能完整性：不破坏现有的 Markdown 渲染和编辑功能

## Non-Goals (Out of Scope)

1. 不重写整个编辑器架构（保留 Monaco Editor 作为核心编辑引擎）
2. 不改变现有的 Markdown 渲染引擎（继续使用 remark/rehype）
3. 不修改表格、代码块等复杂元素的渲染逻辑（仅控制语法标记的显示/隐藏）
4. 不添加任何新的 Markdown 语法支持

## Background & Context

当前 WeaveMD 使用双栏模式（左侧 Monaco Editor 编辑，右侧实时预览）。虽然这是一种常见的 Markdown 编辑模式，但用户反馈希望获得更流畅的即时编辑体验。此次升级将采用类似 Typora 的交互模式，在同一个视图中实现编辑与预览的无缝切换。

## Functional Requirements

### FR-1: 浮动工具栏位置优化

- 将工具栏与选中内容的垂直间距进一步缩小（从当前 10px 调整为 5px）
- 将工具栏向右移动一大段距离（从当前的居中位置调整为靠右对齐）
- 保持工具栏的水平居中参考点为选中文本的右侧边缘

### FR-2: 移除预览模式

- 从 UI 中完全移除预览模式切换选项
- 从状态管理中移除 `isPreviewMode` 相关状态
- 从 MainPage 中移除双栏布局逻辑，统一为单一编辑视图
- 更新相关文档和代码引用

### FR-3: 区块语法标记的智能显示/隐藏

- **区块检测**: 当光标移动时，自动检测当前光标所在的 Markdown 区块类型
  - 标题区块（# ## ### 等）
  - 强调区块（**粗体**、_斜体_、**下划线**）
  - 列表区块（- 无序列表、1. 有序列表、- [ ] 任务列表）
  - 引用区块（> 引用）
  - 代码区块（\`行内代码\`、\`\`\`代码块\`\`\`）
  - 链接区块（[文本](链接)）
  - 表格区块

- **语法显示**: 当光标进入某一区块时，该区块的完整原始 Markdown 语法字符将被显示
  - 例如：光标在标题中时，显示 "# 标题文本" 而非仅显示 "标题文本"
  - 例如：光标在粗体文本中时，显示 "**粗体文本**"

- **语法隐藏**: 当光标离开某一区块时，该区块的语法标记自动隐藏，仅呈现美化后的渲染效果
  - 例如：光标离开标题后，"# " 隐藏，只显示 "标题文本" 并应用标题样式
  - 例如：光标离开粗体后，"**" 隐藏，只显示加粗的文本

- **区块边界**: 清晰定义每个区块的边界，确保语法标记的显示/隐藏在正确的范围内生效

### FR-4: 保持现有渲染逻辑

- 继续使用现有的 remark/rehype 渲染引擎
- 不修改已有的 Markdown 解析和渲染逻辑
- 仅在显示层面控制语法标记的可见性
- 保持对所有现有 Markdown 语法的支持

## Non-Functional Requirements

- **NFR-1**: 性能要求 - 语法标记的显示/隐藏切换响应时间 < 100ms
- **NFR-2**: 稳定性要求 - 不因为新功能引入任何崩溃或数据丢失
- **NFR-3**: 兼容性要求 - 保持与现有数据格式完全兼容
- **NFR-4**: 可访问性要求 - 确保新的交互模式不会影响键盘操作和屏幕阅读器支持

## Constraints

- **Technical**: 必须继续使用 Monaco Editor 作为编辑引擎，不能替换为其他编辑器
- **Technical**: 必须保留现有的 remark/rehype 渲染管道
- **Business**: 此次升级不能影响任何现有功能的正常使用
- **Dependencies**: 依赖 Monaco Editor 的 Decorations API 来实现语法标记的显示/隐藏

## Assumptions

1. 用户理解并接受类似 Typora 的编辑模式
2. Monaco Editor 的 Decorations API 足够灵活来实现所需的语法标记控制
3. 区块检测可以通过解析当前行或选区的文本内容来实现
4. 性能能够满足即时切换的要求

## Acceptance Criteria

### AC-1: 浮动工具栏位置优化

- **Given**: 用户在编辑器中选中一段文本
- **When**: 浮动工具栏显示
- **Then**: 工具栏与选中文本的垂直间距为 5px，且工具栏靠右对齐（以选中文本右侧为参考）
- **Verification**: human-judgment

### AC-2: 预览模式完全移除

- **Given**: 用户打开 WeaveMD
- **When**: 查看界面
- **Then**: 界面中没有任何预览模式相关的切换按钮或选项，只有单一编辑视图
- **Verification**: human-judgment

### AC-3: 光标进入区块时显示语法

- **Given**: 用户在编辑 Markdown 文档
- **When**: 光标移动到标题、粗体、列表等区块内
- **Then**: 该区块的完整原始 Markdown 语法（如 #、**、- 等）完整显示
- **Verification**: human-judgment

### AC-4: 光标离开区块时隐藏语法

- **Given**: 光标在显示语法的区块内
- **When**: 光标移动到该区块外部
- **Then**: 该区块的语法标记立即隐藏，仅显示美化后的渲染效果
- **Verification**: human-judgment

### AC-5: 语法标记切换响应迅速

- **Given**: 用户在编辑器中移动光标
- **When**: 光标跨越区块边界
- **Then**: 语法标记的显示/隐藏在 100ms 内完成，无明显延迟
- **Verification**: human-judgment

### AC-6: 现有功能保持完整

- **Given**: 此次升级完成后
- **When**: 用户使用所有现有的编辑功能（浮动工具栏、快捷键、自动保存等）
- **Then**: 所有功能正常工作，与升级前一致
- **Verification**: programmatic + human-judgment

## Open Questions

1. **复杂嵌套结构的处理**: 对于嵌套的 Markdown 结构（如列表中的粗体），如何确定区块边界？
   - 暂定方案：以最内层的语法元素为优先显示单位
2. **表格的处理**: 表格的语法标记较为复杂，是否需要特殊处理？
   - 暂定方案：表格内的语法标记始终显示，不进行自动隐藏

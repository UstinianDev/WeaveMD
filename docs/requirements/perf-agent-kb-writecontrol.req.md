# 性能优化需求：智能创作Agent / 搜索知识库 / 写控制与任务安全

> 生成时间：2026-09-11
> 任务级别：L 级（跨模块，多天）
> 优化范围：全部瓶颈（B1-B10）

---

## 一、优化目标

### 1.1 核心目标

- **执行速度** > 可读性 > 质量
- 行为不变：相同输入 → 相同输出
- 端到端连通性保证

### 1.2 量化目标

| 指标 | 当前基线 | 目标值 | 提升幅度 |
|------|----------|--------|----------|
| Agent 单轮延迟 | ~200ms | ~100ms | 50% |
| KB 搜索延迟 | ~150ms | ~80ms | 47% |
| 事件持久化延迟 | ~15ms/event | ~5ms/event | 67% |
| 快照创建延迟 | ~500ms | ~200ms | 60% |

---

## 二、优化清单

### 2.1 P0 必须优化（高优先级）

#### B1: Checkpoint 增量写入

**当前状态**: 每轮工具执行后全量序列化 `CheckpointData`（含所有历史消息）并写入 DB

**优化方案**:
- 增量写入：只序列化本轮新增的 `toolTurn` 消息
- 合并策略：读取现有 checkpoint → 合并新消息 → 写入
- 可选：异步写入（不阻塞主循环）

**验收标准**:
- [ ] Checkpoint 写入延迟降低 60%+
- [ ] 断线重连后能正确恢复会话
- [ ] 回归测试全绿

**风险**: 中（需要确保增量合并的正确性）

---

#### B2: 消息历史分页加载

**当前状态**: `getMessagesByConversation` 无 LIMIT，长对话时全表扫描

**优化方案**:
- 分页加载：只加载最近 N 轮消息（如最近 20 轮）
- 索引优化：确保 `ai_messages(conversation_id, created_at)` 索引生效
- 可选：消息摘要压缩（已有 `buildCompressed`，可复用）

**验收标准**:
- [ ] 长对话（100+ 消息）时加载延迟降低 70%+
- [ ] Agent 循环功能正常
- [ ] 回归测试全绿

**风险**: 低（分页逻辑简单）

---

### 2.2 P1 应该优化（中优先级）

#### B3: Token 估算增量更新

**当前状态**: 压缩后全量重算 `ctx.totalTokens`

**优化方案**:
- 增量更新：压缩前记录旧 token 数，压缩后只计算新增消息
- 可选：LRU 缓存（相同内容不重复计算）

**验收标准**:
- [ ] Token 估算延迟降低 50%+
- [ ] 压缩触发阈值准确
- [ ] 回归测试全绿

**风险**: 低（纯计算优化）

---

#### B4: jieba-wasm 异步加载

**当前状态**: `require('jieba-wasm')` 同步阻塞主线程

**优化方案**:
- 异步加载：应用启动时后台加载 jieba-wasm
- 降级策略：加载完成前使用 bigram 分词
- 缓存：加载成功后缓存 `cutForSearch` 引用

**验收标准**:
- [ ] 首次 KB 搜索延迟降低 80%+
- [ ] 分词质量不变
- [ ] 回归测试全绿

**风险**: 中（需要确保异步加载的线程安全）

---

#### B6: 事件批量写入

**当前状态**: 每个事件单独 INSERT + IPC 发送

**优化方案**:
- 批量写入：累积 N 个事件后批量 INSERT（如每 100ms 批量写入）
- 批量 IPC：合并多个 chunk 事件后统一发送
- 保序：确保事件 seq 顺序正确

**验收标准**:
- [ ] 事件持久化延迟降低 60%+
- [ ] 断线重连后事件顺序正确
- [ ] 回归测试全绿

**风险**: 中（需要确保批量写入的事务性）

---

### 2.3 P2 可以优化（低优先级）

#### B5: 标题匹配 FTS5 索引

**当前状态**: `titleMatchSearch` 用 LIKE 查询，无法使用索引

**优化方案**:
- FTS5 索引：为 `kb_documents(title, file_path)` 创建 FTS5 虚拟表
- 查询优化：将 LIKE 查询改为 FTS5 MATCH

**验收标准**:
- [ ] 标题匹配延迟降低 80%+
- [ ] 搜索结果不变
- [ ] 回归测试全绿

**风险**: 低（FTS5 索引成熟稳定）

---

#### B7: 快照增量更新

**当前状态**: 创建快照时查询所有 .md 文件的完整内容

**优化方案**:
- 增量快照：只备份自上次快照后修改的文件
- 差异检测：比较 `modified_at` 时间戳
- 可选：压缩存储（减少快照大小）

**验收标准**:
- [ ] 快照创建延迟降低 70%+
- [ ] 回滚功能正常
- [ ] 回归测试全绿

**风险**: 中（需要确保增量快照的完整性）

---

#### B8: 文件列表缓存

**当前状态**: 每次 Agent 调用都查询 `listFiles(userId)`

**优化方案**:
- 会话级缓存：同一会话内复用文件列表
- 失效机制：文件创建/删除/重命名时清除缓存
- TTL：会话结束时自动过期

**验收标准**:
- [ ] 文件列表查询延迟降低 90%+
- [ ] 文件操作后缓存正确失效
- [ ] 回归测试全绿

**风险**: 低（缓存逻辑简单）

---

### 2.4 P3 低优先级

#### B9: 搜索缓存优化

**当前状态**: 惰性清理遍历全 Map

**优化方案**:
- LRU 淘汰：使用 LRU 缓存替代 Map
- 容量限制：最大 100 条目，超出时淘汰最旧条目

**验收标准**:
- [ ] 缓存清理延迟降低 80%+
- [ ] 搜索结果不变
- [ ] 回归测试全绿

**风险**: 低（纯数据结构优化）

---

#### B10: Token 估算缓存

**当前状态**: 每次调用都遍历整个字符串

**优化方案**:
- LRU 缓存：相同内容不重复计算
- 容量限制：最大 1000 条目

**验收标准**:
- [ ] Token 估算延迟降低 70%+
- [ ] 估算结果不变
- [ ] 回归测试全绿

**风险**: 低（纯数据结构优化）

## 三、行为不变约束

### 3.1 核心约束

1. **相同输入 → 相同输出**
   - Agent 循环逻辑不变
   - KB 搜索结果不变
   - 写控制逻辑不变

2. **功能行为不变**
   - 断线重连功能正常
   - 回滚功能正常
   - 事件持久化正常

3. **仅改变执行速度**
   - 不改变任何模块的功能行为
   - 不改变 API 接口
   - 不改变数据结构

### 3.2 测试约束

- 回归测试必须全绿
- 行为守护测试必须通过
- 性能基准测试必须有数据对比

## 四、风险评估

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 行为变化 | 中 | 功能异常 | 回归测试 + 行为守护 |
| 缓存一致性 | 中 | 数据不一致 | TTL + 失效机制 |
| 异步错误 | 低 | 偶发失败 | try-catch 兜底 |
| 内存泄漏 | 低 | 内存膨胀 | LRU + 容量限制 |
| 并发安全 | 低 | 数据竞争 | 事务 + 锁机制 |

# notus-agent-clone — 需求文档

> 创建日期: 2026-08-24
> 状态: 对齐中

## 一、项目目标

深度模仿 Notus 项目的 AI Agent 功能，采用完全替换策略（不用兼容层），将 WeaveMD 的 AI Agent 系统升级到 Notus 架构水平。

## 二、用户决策

- **范围**: 全量 P0+P1+P2（21 项全部实现）
- **重构策略**: 完全替换（直接用 Notus 架构替换现有实现）

## 三、需求清单

### P0 — 核心体验（6 项）

| ID | 功能 | 目标 | 验收标准 |
|----|------|------|----------|
| P0-1 | A2: Agent Session 状态机扩展 | 从 3 状态扩展到 10+ 状态 | 状态机覆盖所有生命周期，状态转换正确 |

| P0-5 | B5: preview_patch_files 工具 | 多文件补丁预览 | 支持 old/new 补丁对比预览 |
| P0-6 | A8: 文件快照+回滚 | 一键撤销 Agent 所有修改 | session 创建时快照，支持回滚 |

## 四、需要对齐的问题

### 1. 数据库 Schema 变更
- 现有 SQLite 数据库需要新增表（agent_task_queue, agent_run_events, agent_checkpoints 等）
- 需要迁移脚本，向后兼容
- **问题**: 是否需要保留旧数据？迁移策略？

### 2. 状态机状态定义
- Notus 有 10+ 状态，WeaveMD 需要精简还是完全对齐？
- **问题**: 状态转换图是否需要文档化？

### 3. SSE 事件类型
- Notus 的 SSE 事件类型有哪些？需要完整列表
- **问题**: 事件持久化策略（截断、过期清理）

### 4. Checkpoint 数据结构
- checkpoint 需要保存哪些数据？
- **问题**: checkpoint 序列化格式（JSON/MessagePack）

### 5. 文件快照范围
- 快照所有 .md 文件还是仅当前目录？
- **问题**: 快照存储位置（内存/磁盘/DB）

### 6. 提问卡片交互
- ClarifyDrawer 的交互流程细节
- **问题**: 条件依赖如何实现？

### 7. 工具 Schema 校验
- JSON Schema 校验的严格程度
- **问题**: 校验失败的处理策略

### 8. 任务取代策略
- 取消旧任务的时机和条件
- **问题**: 取消后的状态清理

### 9. 前端架构调整
- 三视图 → 统一编排层的迁移路径
- **问题**: 是否需要保留旧组件？

### 10. 测试策略
- L 级 TDD strict，测试覆盖率目标？
- **问题**: E2E 测试范围

## 五、技术约束

- Electron 主进程 + React 渲染进程架构
- SQLite 数据库（better-sqlite3）
- Zustand 状态管理
- 现有 IPC 协议（11 个 handler 模块）
- 现有 AI 基础设施（llmClient, toolRegistry, contextManager 等）

## 六、验收标准

1. 所有 21 项功能实现完成
2. 单元测试覆盖率 ≥ 80%
3. E2E 测试覆盖核心流程
4. 性能无明显退化
5. 向后兼容现有数据
6. 文档完整更新

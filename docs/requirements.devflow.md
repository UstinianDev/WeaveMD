## 1. 目标（Goal）

修复浮动工具栏行内格式化两个交互缺陷（均发生在 Normal Mode）：

| 编号 | 缺陷原文（用户） | 整理后的目标 |
| --- | --- | --- |
| G-① | 不同语法符号持续叠加：`123` 加粗 → `**123**`，选中 `3**` 点斜体 → 产出畸形混合标记（实测 `**12*3***`），非灰度（非聚焦）显示下也出现可见语法残体；再选 `*3*` 点下划线，`<u>` 也叠加出现 | 选区含**其它风格** token 的边界标记时应用新格式，不再产生畸形/字面残体；叠加格式语义正确、可干净渲染 |
| G-② | 灰度显示（块聚焦，`.md-syntax` 灰显）下，指针只选中语法符号拖拽，造成语法符号移位 | 灰度模式下拖选/选区涉及语法符号时，标记字符在后续操作（格式化/删除/光标恢复）中不再移位、不再被误当作内容处理 |

> 已核实：G-① 与 FT3 已处理的"同风格叠加"（C10/C11/C12）**部分重叠但不相同**——FT3 Step 0
> 只对**同风格** token 做归一化（`findIntersectingStyleTokens` 按 `STYLE_TOKEN_TYPE[style]` 过滤），
> 选区跨**异风格**标记时无任何吸附，走 Step 2 裸包裹。详见第 4 节证据。

## 2. 范围（Scope）

### 本次范围（In）

- 行内格式（bold/italic/underline/strike/highlight/code/math）跨风格混合选区的归一化逻辑（formatCtrl + inlineLexer）。
- 相邻混合强调标记的渲染识别扩展（如 `**12*3***`、`**12***3***` 类组合），使其可干净解析、无字面残体。
- **纯内容部分选区（U6 纳入）**：`**abc**` 选 `ab`（纯内容、不覆盖标记）点异风格 → 同样归一化，包裹时与相邻异风格标记正确合并、不产生畸形序列。
- 灰度模式下选区/拖选涉及 `.md-syntax` 标记字符时的偏移与操作安全（含拖选路径验证）。
- 相关 Vitest 单测与 Playwright E2E（含 G-② 的拖选复现用例）。
- 文档同步：本规范/需求、modules/04、SUMMARY、TDD 证据。

### 范围外（Out，仅记录不处理）

- `.md-syntax` 灰度显示规则本身（方案 B 保持：非聚焦隐藏、聚焦灰显）——除非用户确认要调整。
- 块级语法（列表 marker、任务复选框、标题 `::before`、引用竖线）——已有独立机制（contenteditable=false），不受影响。
- 工具栏驻留 / 尺寸 / 块转换矩阵（FT3 已定行为，零变化）。
- display math `$$…$$`、图片粘贴、列表间互转等既有范围外事项。
- 键盘快捷键路径（`Ctrl+B` 等）行为（当前与工具栏路径共用 formatCtrl，改动需回归确认，但不改其折叠光标语义）。

## 4. 查证证据（已核实，阶段 1）

### 4.1 G-① 复现（vitest 实测，临时用例已删）

| 输入 | 操作 | 实际输出 | 说明 |
| --- | --- | --- | --- |
| `**123**` | 选区 `[4,7)`（`3**`）点 italic | `**12*3***` | **畸形**：`tokenizeInline` 解析为 strong(`12*3`) + 字面 `*`；中间/尾部 `*` 为普通文本，非 `.md-syntax` → 非聚焦仍可见 |
| `**abc**` | 选区 `[2,5)`（内容 `abc`）点 italic | `***abc***` | FT3 C12 已覆盖，渲染 em 内嵌 strong，干净 |
| `**12*3***` | 选区 `[4,7)`（`*3*`）点 underline | `**12<u>*3*</u>**` | 语义上合法嵌套（strong+em+u），灰度下三层标记同时可见（方案 B 特性） |

### 4.2 根因（代码）

- `formatCtrl.ts:100-137`：Step 0 归一化只处理**同风格**相交 token（`findIntersectingStyleTokens(text, style, …)`，`inlineLexer.ts:424-450` 按 `STYLE_TOKEN_TYPE[style]` 单类型过滤）。选区跨异风格标记时 `toStrip` 为空 → 走 Step 1 toggleOff（不命中）→ Step 2 裸包裹。
- `inlineLexer.ts:307-370` `matchEmphasis`：仅支持 `*`/`**`/三连 `***`（整体），**不支持相邻混合强调**（如 `**12*3***` 的 `**12`+`*3*`+`**`、`**12***3***` 的 strong 尾 + `***3***`），故畸形包裹后无法干净解析。
- `inlineRenderer.ts:95-111` `renderTokenList`：token 间隙的字符 `escapeHtml` 原样输出 → 孤立的 `*` 直接渲染为可见字面字符。

### 4.3 G-② 根因（代码 + 文档，拖选具体路径待 E2E 复现确认）

- `globals.css:1933-1938`：`.md-syntax` 默认 `font-size:0; opacity:0; user-select:none`；`globals.css:1940-1945` 聚焦灰显 `font-size:inherit; opacity:0.55` → **灰度时标记占真实宽度**。
- `user-select:none` 在 **contentEditable 内不阻止选中**（Chromium 既有行为：可编辑区域后代不可经 CSS 禁止选中）→ 灰度模式下拖选可选中标记字符。
- `selection.ts:13-33`（`getCursorOffsets`）与 `selection.ts:102-107`（`offsetInBlock`）把 `.md-syntax` 标记字符**计入文本偏移**；选区含标记时，后续 formatRange（步 4.1）或块树删除会按含标记偏移操作 → 标记相对内容移位。
- 现有 E2E 仅断言**块级**语法不可选中（`e2e/editor.spec.ts:157`，标题 marker/复选框/引用竖线/列表 marker，均为 contenteditable=false 装饰），**无行内 `.md-syntax` 拖选/选中用例**。

### 4.4 已覆盖 / 未覆盖对照

| 场景 | 现有覆盖 | 本次 |
| --- | --- | --- |
| 同风格部分标记（`**123**` 选 `3**`/`**123` 点加粗）→ 解除 | ✅ FT3 C2/E1 | — |
| 同风格跨多 token 覆盖标记 → 逐 token 解除 | ✅ FT3 C10/E6 | — |
| 纯内容选区点异风格 → 三连 `***` 叠加 | ✅ FT3 C12/E7 | — |
| **选区含异风格标记点异风格（`**123**` 选 `3**` 点斜体）** | ❌ 无 | G-① |
| **叠加后相邻混合标记（`**12*3***`）干净渲染** | ❌ 无 | G-① |
| **灰度模式拖选含 `.md-syntax` 标记 → 移位** | ❌ 无 | G-② |

## 5. 假设 / 约束

- 标记继续保留在 DOM/文本层（`textContent` 与源一致、序列化往返不变量）——与 FT2/FT3 一致，不改为"标记从文本移除"的方案。
- 格式语义延续 FT3 的"叠加"方向（加粗+斜体共存，`***` 三连），不倒退为"新格式覆盖旧格式"。
- 本次只动行内格式相关内核/组件；不改块树数据模型、双向转换、六条退出规则、撤销/重做、自动保存、查找替换、大纲。
- 灰度显示规则（方案 B）默认不变，除非用户确认调整。
- 阶段 2 实现前，G-② 需先经 Playwright 拖选复现用例确认具体表现（避免在猜测上设计）。

## 7. 风险

- 风险等级：**L3**（编辑器核心交互/内核行为修改：formatCtrl + inlineLexer + 可能的 selection/拖选路径）。
- 涉及的中高风险改动（阶段 2/3 需明确批准）：
  1. `formatCtrl.ts` Step 0 归一化扩展为跨风格（业务逻辑核心，改动需回归 FT3 C10-C12）。
  2. `inlineLexer.ts` 相邻混合强调解析（**U2 → B 全部两两组合**，行内渲染/剥离/Step 0 共用，影响面大）。
  3. 可能的 `selection.ts` / `useCrossBlockDragSelection.ts` 标记偏移处理（G-②）。
- 不涉及生产部署/密钥/数据迁移（无 L4）。

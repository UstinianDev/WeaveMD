## 瓶颈扫描结果

### M1: AI Agent 模块

| # | 文件:行号 | 规则 | 严重程度 | 描述 |
|---|-----------|------|----------|------|
| B1 | agentLoop.ts:598-606 | PERF-DB | 🟡 中 | `listFiles(userId)` 每轮 prepareAgentContext 全量查询，6+ 轮循环中重复执行 |
| B2 | agentLoop.ts:669 | PERF-CPU | 🟢 低 | `estimateTokens` 对所有消息 reduce 遍历，增量统计已部分优化 |
| B3 | agentLoop.ts:628-657 | PERF-ALLOC | 🟢 低 | system prompt 字符串数组 `.filter(Boolean).join('\n')` 每次重新构建 |
| B4 | toolRegistry.ts:292-294 | PERF-ALLOC | 🟢 低 | `defineCoreTools()` 返回模块级缓存的 CORE_TOOLS，已是 O(1)，无瓶颈 |
| B5 | agentLoopGuard.ts:132-135 | PERF-CPU | 🟢 低 | MD5 hash 每次工具结果，JSON.stringify 大结果可能慢 |

**M1 结论**：agentLoop 已做过增量 token 统计、KB 预加载缓存、chunk 批量 IPC 等优化。
唯一值得优化的是 B1（listFiles 重复查询），其余为微优化，收益 <5%。

### M2: 写控制与任务安全模块

| # | 文件:行号 | 规则 | 严重程度 | 描述 |
|---|-----------|------|----------|------|
| B6 | agentToolPolicy.ts:43-45 | PERF-ALLOC | 🟢 低 | `getToolPolicy()` 每次返回同一对象引用，已是常量 |
| B7 | agentSnapshot.ts | PERF-IO | 🟡 中 | 每次任务启动全量快照所有 .md 文件，大工作区（100+ 文件）耗时 |

**M2 结论**：写控制模块代码量小（<500 行总计），逻辑简单（策略查表 + 快照 + checkpoint）。
B7 是唯一可优化项，但快照是一次性操作，不在热路径上。

### M3: 搜索知识库模块

| # | 文件:行号 | 规则 | 严重程度 | 描述 |
|---|-----------|------|----------|------|
| B8 | kbSearch.ts:750-809 | PERF-DB | 🟡 中 | expandedQueries 串行执行 N 次 FTS5 查询（for 循环），可并行 |
| B9 | kbSearch.ts:828-876 | PERF-DB | 🟡 中 | vecDocRows 和 updatedAtMap 两次独立 DB 查询，可合并为一次 JOIN |
| B10 | kbSearch.ts:576-583 | PERF-ALLOC | 🟢 低 | cleanupSearchCache 对 Map entries 排序创建新数组，大缓存时有 GC 压力 |
| B11 | kbIndexer.ts:147-173 | PERF-NET | 🟢 低 | embedding 批量调用已有 EMBED_BATCH_SIZE=20 分批，无瓶颈 |

**M3 结论**：kbSearch 已做过 RRF 三路并行、批量邻居查询、惰性缓存清理等优化。
B8（expandedQueries 串行→并行）和 B9（两次 DB 查询合并）有优化空间，其余为微优化。

## 优化必要性判断

| 模块 | 瓶颈 | 值得优化？ | 理由 |
|------|-------|-----------|------|
| M1 Agent | B1 listFiles 重复查询 | ✅ 是 | 热路径，多轮循环中每轮执行，缓存可省 ~5-10ms/轮 |
| M1 Agent | B2-B5 | ❌ 否 | 微优化，收益 <5%，代码已高度优化 |
| M2 写控制 | B7 快照 | ❌ 否 | 一次性操作，不在热路径，大工作区场景罕见 |
| M2 写控制 | B6 策略 | ❌ 否 | 已是常量引用，零开销 |
| M3 知识库 | B8 扩展查询并行化 | ✅ 是 | N 次串行 FTS5 → 并行，3+ 扩展查询时节省 ~60% 延迟 |
| M3 知识库 | B9 DB 查询合并 | ✅ 是 | 减少 1 次 DB roundtrip，每次搜索节省 ~2-5ms |
| M3 知识库 | B10 缓存清理 | ❌ 否 | 惰性清理已优化，极端场景才触发 |

**最终优化清单**：B1 + B8 + B9（共 3 项，预计总提升 10-15%）
